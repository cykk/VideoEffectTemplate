# 单产品模板型 Monorepo 结构说明

## 1. 目标定位

当前仓库不是“多个产品共用一个后端平台”的总仓，而是：

- 一个单产品模板仓库
- 未来可复制出新的 SaaS 产品
- 每个新产品再独立演进、独立部署

## 2. 当前目录结构

```text
apps/
  web/
  api/
packages/
  shared/
```

### `apps/web`

负责：

- 页面
- 组件
- 营销站
- 用户界面
- 轻量 SSR
- 管理后台前端界面

### `apps/api`

负责：

- 认证
- API
- 上传
- Webhook
- SSE
- 图片/视频任务处理
- 支付、订阅、积分

### `packages/shared`

负责：

- 类型
- 常量
- i18n
- 共享工具
- 通用服务封装
- 数据库 schema

## 3. 为什么采用这种结构

这套结构适合当前项目的原因是：

- 便于前后端分开部署
- 后续复制出新产品时结构统一
- 不会像重型大仓一样过度平台化
- 比单体 Next 应用更利于长期维护和扩展

## 4. 部署映射

- `apps/web` → Vercel
- `apps/api` → Fly.io

## 5. 本地开发映射

- `pnpm run dev`：同时启动 Web 与 API
- `pnpm run dev:web`：只启动前端
- `pnpm run dev:api`：只启动后端

## 6. 后续演进建议

当前阶段不建议继续过度拆包。

后续只有在以下前提成立时，再考虑新增包：

- 多个产品稳定复用同一套能力
- 包边界已经稳定
- 不会引入额外的耦合和维护成本

优先保持：

- `apps/web`
- `apps/api`
- `packages/shared`

作为长期模板的最小稳定结构。

# 日常开发模式建议

## 1. 当前标准结构

当前项目采用单仓双应用结构：

```text
apps/
  web/
  api/
packages/
  shared/
```

职责划分：

- `apps/web`：页面、营销页、前端交互、轻量 SSR、浏览器同源 API 入口
- `apps/api`：认证、数据库、支付、上传、Webhook、SSE、图片/视频处理
- `packages/shared`：共享类型、配置、i18n、服务封装、通用工具

## 2. 推荐日常开发模式

推荐长期采用“同仓双进程 + 浏览器同源 `/api/*`”模式。

也就是：

- 本地同时启动 `apps/web` 和 `apps/api`
- 浏览器只访问 `web`
- 浏览器看到的 API 地址始终是当前页面同源 `/api/*`
- `apps/web` 在服务端把这些请求转发给 `apps/api`

## 3. 启动方式

在项目根目录执行：

```bash
pnpm run dev
```

或分别启动：

```bash
pnpm run dev:web
pnpm run dev:api
```

本地端口：

- `apps/web`：`http://localhost:3000`
- `apps/api`：`http://localhost:3001`

## 4. 浏览器入口

### 4.1 日常页面开发

如果只做页面开发、样式开发、普通交互开发，可以直接访问：

```text
http://localhost:3000
```

### 4.2 需要 OAuth / 支付 / Webhook 联调

使用 Cloudflare Tunnel 后，浏览器入口改为：

```text
https://web-dev.watermarkremover.tech
```

同时启动隧道：

```bash
cloudflared tunnel run watermarkremover-local-dev
```

## 5. 当前请求模型

当前项目的请求模型应固定理解为：

- 页面请求：浏览器 → `apps/web`
- 普通业务 API：浏览器 → `apps/web/api/*` → `apps/api`
- OAuth 回调：第三方 → `apps/api`
- 支付 webhook：第三方 → `apps/api`
- Replicate webhook：第三方 → `apps/api`
- 视频��件上传：浏览器直传 R2

这意味着：

- 浏览器不再直接跨域调用 `api` 域名作为主业务入口
- `apps/api` 仍然是唯一真实后端
- `apps/web` 负责浏览器侧同源代理/BFF

## 6. 开发规则

建议固定遵守以下规则：

- 页面、组件、前端状态、前端路由放在 `apps/web`
- 认证、数据库、支付、上传、任务处理、Webhook 放在 `apps/api`
- 公共类型、共享服务、配置封装放在 `packages/shared`
- 浏览器端接口调用统一使用相对路径 `/api/*`
- 不再新增“浏览器直连 `api` 域名”的前端调用

## 7. 为什么推荐这种模式

原因很直接：

- 浏览器视角保持同源，减少 CORS / Cookie / Tunnel 不稳定问题
- 本地和生产链路更接近
- OAuth、支付、用户态 Header、首屏 bootstrap 更稳
- 后端仍保持独立部署，后续扩容和迁移不受影响

## 8. 上线映射

当前结构推荐的上线映射：

- `apps/web` → Vercel
- `apps/api` → Fly.io

生产环境同样建议：

- 浏览器只访问 `web`
- `web` 代理到 `api`
- 第三方 webhook / OAuth callback 直接打 `api`

## 9. 日常验证动作

每次改动认证、支付、上传、SSE、任务处理后，建议执行：

```bash
pnpm run build:web
pnpm run build:api
```

涉及完整业务联调时，再用双域测试入口验证：

```text
https://web-dev.watermarkremover.tech
```

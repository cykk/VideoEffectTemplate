# 双域模式-本地联调测试步骤

适用范围：
- 前端：`apps/web`
- 后端：`apps/api`
- 浏览器联调入口：`https://web-dev.watermarkremover.tech`
- API 公网域名：`https://api-dev.watermarkremover.tech`

## 1. 当前联调模型

当前项目的双域联调采用以下模型：

- 浏览器页面入口：`https://web-dev.watermarkremover.tech`
- 浏览器普通业务请求：`https://web-dev.watermarkremover.tech/api/*`
- 浏览器认证请求：`https://web-dev.watermarkremover.tech/api/auth/*`
- `apps/web` 再把 `/api/*` 转发到：`https://api-dev.watermarkremover.tech/api/*`
- `apps/web` 的 SSR 预加载请求优先通过 `INTERNAL_API_BASE_URL` 直连本地 API：`http://127.0.0.1:3001`

例外链路：
- Google OAuth 回调：仍使用 `https://api-dev.watermarkremover.tech`
- 支付 webhook：仍使用 `https://api-dev.watermarkremover.tech`
- Replicate webhook：仍使用 `https://api-dev.watermarkremover.tech`
- 视频文件上传：浏览器拿到签名后，仍直接上传到 R2

## 2. 环境文件

双域模式固定使用：
- `.env.web.local`
- `.env.api.local`

### 2.1 `.env.web.local`

```env
NEXT_PUBLIC_WEB_URL=https://web-dev.watermarkremover.tech
INTERNAL_API_BASE_URL=http://127.0.0.1:3001
API_UPSTREAM_URL=https://api-dev.watermarkremover.tech
NEXT_PUBLIC_BROWSER_AUTH_BASE_URL=https://web-dev.watermarkremover.tech
NEXT_PUBLIC_BROWSER_SSE_BASE_URL=https://api-dev.watermarkremover.tech
NEXT_PUBLIC_APP_URL=https://api-dev.watermarkremover.tech
NEXT_PUBLIC_AUTH_BASE_URL=https://api-dev.watermarkremover.tech
BETTER_AUTH_URL=https://api-dev.watermarkremover.tech
BETTER_AUTH_TRUSTED_ORIGINS=https://web-dev.watermarkremover.tech,https://api-dev.watermarkremover.tech,http://localhost:3000
AUTH_COOKIE_DOMAIN=watermarkremover.tech
NEXT_DIST_DIR=.next-web
```

说明：
- `INTERNAL_API_BASE_URL` 只给 `apps/web` 服务端使用
- `RootLayout`、bootstrap 预加载、服务端鉴权辅助逻辑等 SSR 请求优先走 `INTERNAL_API_BASE_URL`
- `API_UPSTREAM_URL` 是 `apps/web` 代理层真正转发到的后端地址
- `NEXT_PUBLIC_BROWSER_AUTH_BASE_URL` 明确把 Better Auth 客户端固定到 `web` 同源入口，避免浏览器侧认证请求基址歧义
- `NEXT_PUBLIC_BROWSER_SSE_BASE_URL` 明确把浏览器侧 SSE 长连接直连到 `api-dev`，避免 `apps/web -> apps/api` 代理转发长连接时出现连接重置
- 浏览器端业务接口与认证接口都统一访问当前站点同源 `/api/*`
- `NEXT_PUBLIC_APP_URL`、`NEXT_PUBLIC_AUTH_BASE_URL` 仍保留给 OAuth 回调锚点和兼容逻辑使用

### 2.2 `.env.api.local`

```env
NEXT_PUBLIC_WEB_URL=https://web-dev.watermarkremover.tech
NEXT_PUBLIC_APP_URL=https://api-dev.watermarkremover.tech
NEXT_PUBLIC_AUTH_BASE_URL=https://api-dev.watermarkremover.tech
BETTER_AUTH_URL=https://api-dev.watermarkremover.tech
BETTER_AUTH_TRUSTED_ORIGINS=https://web-dev.watermarkremover.tech,https://api-dev.watermarkremover.tech,http://localhost:3000,http://localhost:3001
AUTH_COOKIE_DOMAIN=watermarkremover.tech
PAYMENT_SUCCESS_BASE_URL=https://web-dev.watermarkremover.tech
REPLICATE_WEBHOOK_BASE_URL=https://api-dev.watermarkremover.tech
NEXT_DIST_DIR=.next-api
```

## 3. 启动方式

### 3.1 启动本地 Web 和 API

在项目根目录执行：

```bash
pnpm run dev
```

或者分开启动：

```bash
pnpm run dev:web
pnpm run dev:api
```

本地监听端口：
- `apps/web`：`http://localhost:3000`
- `apps/api`：`http://localhost:3001`

### 3.2 启动 Cloudflare Tunnel

在另一个终端执行：

```bash
cloudflared tunnel run watermarkremover-local-dev
```

当前隧道名称固定为：

```text
watermarkremover-local-dev
```

## 4. 请求链路说明

### 4.1 浏览器请求

浏览器侧统一这样访问：

- 页面：`https://web-dev.watermarkremover.tech`
- 普通业务接口：`https://web-dev.watermarkremover.tech/api/*`
- 认证接口：`https://web-dev.watermarkremover.tech/api/auth/*`

不要让浏览器日常直接访问：

- `https://api-dev.watermarkremover.tech/api/*`
- `https://api-dev.watermarkremover.tech/api/auth/*`

### 4.2 `apps/web` 服务端请求

`apps/web` 的服务端预加载逻辑，例如：

- `RootLayout`
- bootstrap 预加载
- 服务端鉴权辅助逻辑

优先访问：

- `http://127.0.0.1:3001/api/*`

这样做的目的：

- 避免 SSR 依赖公网 tunnel
- 避免 Cloudflare Tunnel 抖动时，首页服务端预加载直接报 `HTML 502`
- 保持浏览器链路与 SSR 链路职责分离

## 5. 浏览器访问规则

联调时遵守以下规则：

- 页面只从 `https://web-dev.watermarkremover.tech` 打开
- 浏览器 Network 中的普通业务接口，应主要看到 `https://web-dev.watermarkremover.tech/api/*`
- 浏览器 Network 中的登录请求，应主要看到 `https://web-dev.watermarkremover.tech/api/auth/*`
- 不要再用浏览器直接访问 `https://api-dev.watermarkremover.tech` 作为日常业务入口
- 不要混用旧的 `lvh.me`、`localhost:3000`、`localhost:3001` 作为浏览器主入口

## 6. Google OAuth 配置

Google Cloud Console 中：

- 已获授权的 JavaScript 来源：

```text
https://web-dev.watermarkremover.tech
```

- 已获授权的重定向 URI：

```text
https://api-dev.watermarkremover.tech/api/auth/callback/google
```

## 7. 支付与 Webhook

当前双域模式下：

- 支付成功 / 取消回跳页：`https://web-dev.watermarkremover.tech`
- 支付 webhook：`https://api-dev.watermarkremover.tech`
- Replicate webhook：`https://api-dev.watermarkremover.tech`

因此：

- 不需要再额外启动 `ngrok http 3000`
- 不需要再额外启动 `ngrok http 3001`
- 本地双域联调统一通过 Cloudflare Tunnel 完成

## 8. 视频上传链路

视频处理仍然是下面这条链路：

1. 浏览器请求 `https://web-dev.watermarkremover.tech/api/storage/r2/upload-url`
2. `apps/web` 代理到 `apps/api`
3. `apps/api` 返回 R2 直传签名 / 上传地址
4. 浏览器拿到签名后，直接把视频上传到 R2
5. 浏览器再通过同源 `/api/*` 提交后续处理任务

视频文件本体不经过 `apps/web` 中转。

## 9. 验证清单

建议按以下顺序验证：

1. 打开 `https://web-dev.watermarkremover.tech`
2. 浏览器 Network 中，普通业务接口应以 `https://web-dev.watermarkremover.tech/api/*` 为主
3. 浏览器 Network 中，Google 登录发起请求应以 `https://web-dev.watermarkremover.tech/api/auth/*` 为主
4. `apps/web` 服务端日志中，`RootLayout` 不再因为请求 `https://api-dev.watermarkremover.tech/api/user/bootstrap` 返回 HTML 502 而报错
5. Google 登录可正常跳到 `api-dev` 回调
6. 支付创建成功后，回跳到 `web-dev`
7. 图片 / 视频处理、SSE、上传链路正常
